# Muse へ渡す指示文

以下を、この資料フォルダ（README.md と docs/ 一式）と一緒に Muse に渡してください。

---

添付資料をもとに、Apex Legends のマップローテーション確認アプリ「Apex マップローテーション」を、私が利用する Muse のフルスタック・スペース上に構築してください。GitHub リポジトリの新規作成や外部公開は不要です。

## 実装前の確認

- README.md と docs/ 一式を読み、機能仕様は `docs/SPEC.md`、画面デザインは `docs/DESIGN.md`、データ取得・予測は `docs/DATA.md`、公式ニュースの取得は `docs/UPDATES.md`、実装構成は `docs/ARCHITECTURE.md` に従うこと。公式ニュースの画面表示件数は SPEC.md の2本立て・各最大3件を優先すること
- Muse のスペース、永続保存、サーバーアクション、15分間隔の定期ジョブ、チャット通知、公開データ取得が利用可能か確認すること。利用できない機能は未対応として報告し、未確認の機能を実装済みとしないこと
- 既存のスペースやジョブは変更せず、新たな外部サービス・有料API・公開リンクを無断で作らないこと

## 作るもの

- モード別（ランク／バトルロイヤル／ミックステープ／ワイルドカード）に「現在のマップ」「残り時間のカウントダウン」「次のマップ」「以後数件の予定（予測は予測と明示）」を表示する Muse スペース
- ミックステープはモード種別（チームデスマッチ／コントロール／ガンゲーム）＋マップ名で表示する。導出方法と安全策は `docs/DATA.md` の通りとし、マップ名が対応表と一致しない場合はモードを表示しないこと。ワイルドカードは予測補完せず、未定と明示すること
- お気に入りマップの登録・解除は Muse の永続保存機能で実装し、ライブ中は強調表示すること
- 公式アップデートは画面下部に、EA Japan の日本語記事（最大3件）と Steam News の英語記事（最大3件）を分けて表示すること。取得は X に依存せず、日付・タイトル・リンクの1行リストとし、詳細は `docs/UPDATES.md` と `docs/SPEC.md` に従うこと
- お気に入りマップの開始前通知設定（ON/OFF、既定OFF、0/15/30/60分のプリセット＋任意入力、対象モードの複数選択）を永続保存すること。Muse の定期チェックで設定とローテーションを照合し、チャットへ通知する設計とする。通知時刻にはチェック間隔による誤差があることを明記すること

## データ取得と保存

- `docs/DATA.md` の方法（apexdb.gg の埋め込みデータ、15分間隔）を使い、公式ニュースも同じ定期ジョブで取得すること
- `docs/ARCHITECTURE.md` の Muse 版に従い、サーバーアクション `getRotation`（保存済みを即返却）、`refreshRotation`（取得して保存）、`toggleFavorite` を実装すること。ローテーションは `rotation_snapshots` の最新1件、ニュース・お気に入り・通知設定も永続保存すること
- 初回表示は保存済みデータを即描画し、外部取得を待たないこと。残り時間は end 時刻から毎秒クライアント側で計算し、表示のために通信しないこと。手動更新ボタンで再取得できるようにすること
- 取得失敗時は前回のデータを維持し、取得時刻・エラーを確認できるようにすること。APIキー不要の取得方法を基本とし、代替APIキーを使う場合は利用者の承認後にサーバー側でのみ扱うこと

## デザイン（重要）

- 配色・レイアウト・ロゴは、本プロジェクトのデザイン指針に基づいて作成すること
- デザインは `docs/DESIGN.md` の「Muse仕様」に従うこと：オフホワイト基調、アクセント単色（コーラル系）、白カード＋細い罫＋小さなチップ、4モードを2×2タイルで一画面に収めるダッシュボード型グリッド構成（NEXT／NEXT 2／NEXT 3 の3行表示）、数字だけ大きく、説明は短いラベルだけ
- 各タイルの経過率をプログレスバーで表示し、4つ先以降の予定はタイルをタップしたときにグリッド下へ展開すること。マップ名は日本語を主とし、英語名を添えること
- 非公式ファンメイドであり EA / Respawn と無関係である旨と、データ出典（Apex Legends Status / apexdb.gg）を画面下部に明記すること

## 構築・検証・運用開始

1. Muse 上で自分用のスペースを構築し、画面と保存・取得の各機能を実装する。
2. 取得済みデータまたは合成データで2×2表示、NEXT 3、毎秒カウントダウン、予測の表示・停止、お気に入りと通知設定の保存、取得失敗時の前回データ保持を検証する。
3. 実データ取得・保存・読み戻し、公式ニュース表示、手動更新を検証し、成功した点・未対応・制約を利用者に報告する。
4. 利用者の承認後に Muse の15分間隔の定期ジョブを登録し、`refreshRotation` と通知チェックが動くことを確認する。通知は既定OFFのままとし、利用者が有効化した場合のみチャットへ送る。

成果物は Muse 上で利用できるスペースと、その構築・検証結果です。GitHub 公開用ソースや別のホスティングへのデプロイは必須ではありません。
