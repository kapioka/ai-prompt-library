# 機能仕様 SPEC

## 1. 目的

Apex Legends はマップをプレイヤーが選べず、時間で自動的に切り替わる。本アプリは「今どのマップか、あと何分か」をゲーム外から一目で確認するためにある。

## 2. 対象モード

| キー | 表示名 | ローテーション間隔（目安） |
|---|---|---|
| ranked | ランク | 約4時間30分 |
| battle_royale | バトルロイヤル（カジュアル） | 約1時間30分 |
| ltm | ミックステープ | 15分 |
| wildcard | ワイルドカード | 長期（イベント単位） |

## 3. 画面仕様

- 構成はダッシュボード型グリッド：4モードを 2×2 タイルで一画面に収める（レイアウト詳細は `DESIGN.md`）
- 各タイルに「モード名チップ」「現在のマップ」「残り時間（毎秒カウントダウン）」「スロット経過率のプログレスバー」「NEXT／NEXT 2／NEXT 3（マップ名＋開始時刻）」を表示する。行ラベルは改行や意味の誤解を避けるため英文＋数字で統一し、区別は文字の太さと色の段階でも付ける
- タイルをタップすると、4つ先以降のスロットをグリッド下に展開表示する。予測補完したスロットには「予測」と明示する（補完方法は `DATA.md`）。予測できないモードは「以降は未定」と明示する
- ミックステープはモード種別を主表示にする（例：コントロール／生産工場、次はガンゲーム／スカルタウン）。導出方法は `DATA.md` 参照
- マップ名は日本語名を主に、英語名を添える
- お気に入り：マップを★で登録できる。登録は永続化され、お気に入りが現在ライブ中のタイルは強調表示する
- 手動「更新」ボタンで即時再取得できる
- 初回表示は保存済みスナップショットを即座に描画する（外部取得を待たない）。開いた直後の自動再取得は行わない

## 4. データモデル

### rotation_snapshots（最新1件を保持）

- `payload`: モード別スロット配列 `[{ mode, map, start, end, projected? }]`
  - `start` / `end` は Unix 秒（UTC）
- `source_fetched_at`: 取得時刻
- `fetch_error`: 取得失敗時の記録（表示は前回スナップショットを維持）

### favorites

- `map`: マップ識別子（英語名）
- 登録日時

## 5. 更新ルール

- サーバー側の定期ジョブが15分ごとにデータソースから取得し、スナップショットを差し替える
- クライアントの残り時間表示は、保存済み `end` 時刻から毎秒再計算する（表示のための通信はしない）
- 取得に失敗した場合は前回スナップショットを表示し続け、エラーで画面を落とさない
- 外部取得にはタイムアウト（10秒目安）を設ける

## 5.5 公式アップデート表示

- 画面下部に「公式アプデ」の帯を置く。2本立てで、上段に EA Japan の日本語記事（最大3件）、下段に Steam の英語記事（最大3件）を、日付（ローカル時刻）＋タイトルの1行リスト＋リンクで表示する
- 取得元は Steam News 公式APIと EA Japan ニュースページ（どちらもXは使わない）。方法と注意点は `UPDATES.md` 参照
- パッチノート系（タグ `patchnotes`）は「アプデ」と目立たせる
- ローテーションと同じ定期ジョブで取得・保存し、表示は保存済みを即返す

## 5.6 お気に入り通知（設定）

- 通知設定を保存する：ON/OFF（既定OFF）、何分前か（プリセット 0/15/30/60 分＋任意入力）、対象モード（複数選択）
- 通知の実行主体はホスト側（Muse版では Muse の定期チェックが設定とローテーションを照合し、チャットへ通知する）
- チェック間隔の都合で通知時刻には数分〜間隔分の誤差が出ることを仕様として明記する

## 6. 非機能要件

- モバイルファースト。数字と短いラベル中心で、長い説明文を置かない
- 縦スクロールが長くなりすぎない構成にする
- 外部フォント等の外部リクエストに表示を依存させない（フォールバックで崩れないこと）
- ホーム画面ウィジェット等のスナップショット表示でも破綻しないよう、開いた直後に画面が作り直されないこと（ローディング表示の出しっぱなし禁止）
